# 横版 2D 游戏地图 BG 与场景组织

Status: wiki
Last verified: 2026-06-11
Sources:
- 2026-06-11 用户反馈：正式 wiki 写通用横版 2D 游戏思路，不绑定具体项目或场景概念。
- 2026-06-11 项目观察：横版 2D 地图 BG、边界、相机范围和交互物件应分层组织。

Summary:
横版 2D 游戏地图可以拆成四层来理解：背景底图、可走区域、相机可见区域、可交互物件。背景底图负责氛围和空间关系；可走区域决定角色能站在哪里、走到哪里；相机可见区域决定玩家能看到多少场景；可交互物件负责玩法状态和反馈。不要把这四件事混在一张图或一个概念里。

BG 的核心职责是提供不可交互的环境舞台。它应该让玩家一眼看懂空间方向、地面高度、主要氛围和场景主题，但不承担交互状态。会发光、置灰、消失、弹提示、响应点击、播放特效或改变状态的内容，都应该独立成物件，而不是画死在 BG 里。

默认生产一张完整横版场景 BG。只有在确实需要前景遮挡、动态灯效、视差层、昼夜状态、破损状态，或不同区域完全不同视觉主题时，才拆成多张或多层。单张 BG 更容易控制构图、边界、角色站位和物件预留位，也更少引入资源管理和编辑器摆放成本。

视角采用 2D 横向侧视 + 轻微俯视。画面应该水平展开，能看到墙面或远景，也能看到足够地面深度，让角色站位和横向移动有可信空间。透视不能过强，不要做成斜俯视 3D 场景、鱼眼镜头或明显近大远小的建筑透视。横版 2D 的 BG 应优先服务正交相机和清晰的行走平面。

构图要先定三条线：可走区、相机安全区、物件预留区。可走区要干净，不要堆满视觉噪声；相机安全区要保证不同屏幕比例下主体不被裁掉；物件预留区要给传送点、入口、NPC、按钮、宝箱、关卡门、提示牌等运行时物件留出位置。先定这些区域，再画细节，比画完再硬调边界稳定得多。

BG 内容只画不可交互环境：地面、墙体、远景、边框、窗、灯、固定装饰、自然物、建筑轮廓和氛围光。不要画玩家、NPC、UI、按键提示、可点击入口、传送台、书本、按钮、文字、水印或运行时特效。所有需要被程序控制的内容，都应该作为独立物件叠在 BG 上。

尺寸和比例应服务目标视口。横版场景通常优先宽屏构图，可以以 16:9 或项目目标分辨率为基线，但关键不是某个固定尺寸，而是保持稳定的长宽比、中心点、地面高度和安全区。替换同类 BG 时，尽量维持这些关系，避免重新调整角色站位、物件坐标、移动边界和相机边界。

生产提示词可以表达为：横版 2D 正交游戏场景背景，轻微俯视，可见地面深度，宽屏构图，主题明确，墙面、地面和远景层次清晰，中央保留干净可走区域，预留可交互物件位置，无角色、无 UI、无文字、无可交互物件、无强透视畸变。负向约束重点排除角色、按钮、标题字、水印、强烈斜俯视和镜头畸变。

How to use:
做横版 2D 地图时，先问三个问题：这张图只是环境底图，还是包含会变化的玩法元素？玩家实际可走区域在哪里？相机在不同屏幕比例下应该看到什么？如果一个元素需要交互、状态变化或特效，就不要画进 BG。

验收新 BG 时，按顺序检查：视角是否横版 2D 友好；地面是否支撑角色站位；可走区是否清晰；相机安全区是否够；交互物件是否没有被画死；替换后是否不需要大幅重调边界和物件坐标。

Boundary:
这是通用横版 2D 游戏地图 BG 和场景组织思路，不绑定具体项目、场景或资源路径。具体项目落地时，仍要回到实际相机、分辨率、角色尺寸、碰撞/边界系统和资源规范复核。
