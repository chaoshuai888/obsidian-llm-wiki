FootLock Case Study

用脚步锁定案例，看懂 Unreal FBIK 到底在干什么

这次不抽象讲“全身 IK”。我们拿 CRFL_FootLock 做例子：角色技能强制转身时，先把一只脚在世界空间钉住，再用 PBIK 把腿链和骨盆反解回这个锁点，避免 Mesh 平滑旋转时脚底打滑。

1
C++ 在转身开始时采样轴脚世界坐标：这就是脚锁的锚点。
2
Control Rig 每帧把锁点转换成脚 effector 的目标位置。
3
PBIK 不直接“移动脚”，而是通过腿、骨盆和约束迭代，让脚尽量回到锁点。

Mesh 平滑转身时：右脚作为世界空间锚点

FootLockPos
世界空间锁点 Pelvis Root
PBIK 反解根 Mesh 从旧朝向
平滑追向新朝向 另一只脚
继续跟随动画

直觉：Actor 逻辑朝向已经瞬间转到目标方向，视觉 Mesh 还在补间。被选作轴的脚必须停在原地，于是 PBIK 每帧把这只脚拉回 FootLockPos。

Case Summary

这个脚锁到底解决什么问题

技能转身时，逻辑 Actor 会先面向目标；为了视觉不突兀，Mesh 会从旧朝向平滑转过去。问题是：Mesh 旋转会带着脚底一起滑。FootLock 的做法是选一只脚当转向轴，把它临时钉在世界空间，再让腿部 IK 去补偿这段视觉旋转。

因

Actor 和 Mesh 暂时不同步

FaceTarget 先把 Actor 转到目标朝向，StartMeshSmooth 再把 Mesh 退回旧朝向，让视觉慢慢追过去。

锁

轴脚被保存成世界锚点

RoatationAxis 选择左脚或右脚。开始平滑转身那一帧，C++ 采样脚 socket 世界坐标，写入 FootLockPos。

解

PBIK 把腿链解回锁点

Control Rig 把锁点变成脚目标，ExcuteFootIK 输入 PBIK。PBIK 负责让脚尽量贴到目标，并让骨盆和腿自然配合。

Whole Pipeline

完整链路：从技能 Notify 到 PBIK 求解

这条链路很重要：左右脚不是 Control Rig 自己猜的，而是技能/动画 Notify 明确告诉系统哪只脚应该作为转向轴。

1

AttackRotation

蒙太奇 Notify 配置 RoatationAxis：左脚、右脚或不锁。

2

读取轴脚

GetRotationSmoothTime 读取 Notify 时间和轴脚配置。

3

Actor 先转

FaceTarget 立即设置 Actor 朝向，让逻辑先对准目标。

4

采样锁点

StartMeshSmooth 把 Mesh 退回旧朝向，并采样轴脚世界坐标。

5

Control Rig 维持目标

CRFL_FootLock 根据 Enable 标记持续输出脚锁目标。

6

PBIK 反解

ExcuteFootIK 把脚目标输入 RigUnit_PBIK。

7

ActorFollow

锁脚期间把骨盆世界位置回传，补偿本地 Actor XY。

Data Contract

跨 C++、AnimBP、Control Rig 的数据约定

脚锁能稳定工作，靠的是很小的一组数据。最核心的是两个 Enable、一个世界锁点、一个 IK Root 行为和一个是否投地的开关。

bEnableLFootLock 是否锁左脚。
bEnableRFootLock 是否锁右脚。
FootLockPos 转身开始时采样到的轴脚世界坐标，是整个脚锁的锚点。
IkBeavior 传给 PBIK 的 RootBehavior，决定骨盆/root 怎么参与。
ShouldBeOnGround 是否把锁点再投到地面。Control Rig 资产变量拼作 SholudBeOnGround。
锁点的核心数学
开始锁定:
AnchorWS = GetSocketLocation(AxisFootBone)
FootLockPos = AnchorWS

锁定期间:
TargetFootWS = FootLockPos

如果需要贴地:
TargetFootWS = FootTrace(FootLockPos, FootHeight)

所以它不是每帧保存上一帧脚位置再补差，而是保存一个世界空间锚点。当前动画脚被 Mesh 旋转带走时，PBIK 会把脚 effector 拉回这个锚点。

Lock Lifecycle

锁定、投地、释放：三个阶段别混在一起

FootLock 的目标点不是永远钉死。锁定时它等于世界锚点；可选投地时它会修正到地面；解锁后它会逐帧插值回动画脚，避免突然弹跳。

锁定中脚目标固定在世界锚点

当 EnableLFootLock 或 EnableRFootLock 为 true，对应脚使用 FootLockPos 或投地后的结果作为目标。

TargetFootWS = FootLockPos
DeltaWS = TargetFootWS - AnimatedFootWS
PBIK 隐式吃掉这个差值
  • 脚目标不跟随当前动画脚。
  • Mesh 旋转造成的脚滑由 IK 反向补偿。
  • 如果 SholudBeOnGround 为 true，会先走 FootTrace。

解锁后脚目标平滑交还给动画

Enable 关闭后，Control Rig 不会立刻清空锁点，而是用 LerpFootPos 让旧目标逐帧追向当前动画脚。

AnimatedFootWS = 当前动画脚世界位置
NextTargetWS = Lerp(OldTargetWS, AnimatedFootWS, 0.5)

如果 XY 距离小于 3:
NextTargetWS = AnimatedFootWS
  • 避免脚目标突然跳回动画位置。
  • 接近后完全交还给动画。
  • 需要贴地时，插值结果还会再过一次 FootTrace。

Where FBIK Appears

这个案例里，FBIK/PBIK 的角色很明确

CRFL_FootLock 本身负责“脚目标应该在哪里”；真正让腿怎么弯、骨盆怎么配合的是 ExcuteFootIK 里的 PBIK。

输入：脚锁目标

LFootLockLocation 或 RFootLockLocation 经过 From World 转换后，写入脚目标 Transform 的 Translation。

Effector：被钉住的脚

FPBIKEffector.Bone 是脚骨骼名，Transform 是锁点目标。默认位置、旋转、强度 alpha 都是满权重。

Root：骨盆

PBIK.Root = PelvisBoneName。这意味着腿和骨盆一起参与折中，而不是只扭小腿或只挪脚。

Settings：IKBehavior

GetIKRootBeavior 把外部整数转换成 PBIK 的 RootBehavior。它决定骨盆是预拉、锁住，还是自由参与。

FootLockPos
-> LFootLockLocation / RFootLockLocation
-> From World
-> FootIkInfo.BoneTransform.Translation
-> FPBIKEffector.Transform
-> RigUnit_PBIK.Solve()

Actor Follow

为什么只锁脚还不够

脚被 PBIK 锁住后，视觉 Mesh 可能和逻辑 Actor 胶囊体产生偏移。这个项目里用 ActorFollow 把骨盆世界位置回传给 UMeshRotationSmoothCpt，再在本地控制端补偿 Actor 的 XY。

补偿思路
锁脚期间:
PelvisWS = ToWorld(Pelvis)
ActorFollow(PelvisWS)

下一帧:
FollowMesh(NewLocation)
UpdateMeshRotation()
Actor.XY 跟随 Mesh
Actor.Z 保持原高度

通俗说：脚钉住以后，角色视觉位置可能被 IK 拉出一点偏移。ActorFollow 把这点偏移同步给 Actor，减少胶囊体和 Mesh 脱节。

Debug Checklist

排查脚锁时按这条顺序看

这个功能跨 Notify、技能系统、Mesh 平滑组件、AnimBP、Control Rig 和 PBIK。别一开始就调 IK 参数，先确认数据有没有一路传到脚 effector。

1. Notify 是否选了正确轴脚

检查蒙太奇里的 AttackRotation，确认 RoatationAxis 是左脚、右脚还是 None。

2. C++ 是否真的启用锁脚

小于 AngleThreshold = 5 度、脚下 trace 失败、脚离地太高，都可能导致 Enable 没打开。

3. AnimBP 是否把数据传给 Control Rig

重点看 Enable*FootLock、FootLockPos、IKBehavior 和 SholudBeOnGround。

4. 锁点是否写进脚目标

检查对应侧的 LFootLockLocation / RFootLockLocation，以及 From World 后的目标 Translation。

5. PBIK 是否收到正确 Root 和 Foot Bone

PelvisBoneName、LFootBoneName、RFootBoneName 错了，锁点再正确也解不到想要的链。

6. ActorFollow 是否执行

如果脚锁住但胶囊体和 Mesh 脱节，继续看 FRigUnit_ActorFollow 和本地端 Actor XY 补偿。

Takeaway

用这个案例反过来理解 FBIK

1. Effector 不是“脚的位置”，而是“脚应该去的目标”。

在 FootLock 里，这个目标就是 FootLockPos 或投地后的锁点。动画脚当前在哪里不重要，PBIK 会把它往目标拉。

2. Root 决定骨盆是否参与补偿。

这里 PelvisBoneName 作为 PBIK Root。RootBehavior 决定骨盆是更自由地跟着脚锁调整，还是更接近输入姿势。

3. PBIK 解的是“误差如何分摊”，不是单纯移动一个骨骼。

TargetFootWS - AnimatedFootWS 的差值被隐含进 IK 求解里，最终由脚、膝盖、髋部、骨盆一起承担。

4. 释放阶段和锁定阶段一样重要。

如果 Enable 一关就直接回动画脚，脚会跳。LerpFootPos 让目标逐帧追回动画脚，视觉上才像“松开”而不是“弹回”。
